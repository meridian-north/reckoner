# The contribution file — one default, reopenable download

**Decision (private candidate, 2026-10-20).** The single user-facing contribution file is the
existing creator-history bundle, `reckoner.creator-history-bundle.v1`, produced by
**Save to file** in the header or **More → Save to file**. No new transport
or envelope was introduced. The bundle already carries everything the exchange requires:

- every retained checkpoint as an **exact receipt snapshot** (`garrison.cairn.receipt.v0.1` bytes,
  base64 inside the bundle, each named by its SHA-256);
- the hash-linked history (`genesis`, `tip`, `exact_snapshot_hash_links_verified`) that detects
  stale copies, rollback and substituted bytes on reopen;
- in the latest receipt: every saved reading with contributor, optional per-reading AI assistance
  note, reason, uncertainty and structured hOCR pin (`revisions[].context.hocr`); reviewer and mentor
  decisions including `needs_review` and `disputed`; declared model records; and prior revisions.

Original source files and hOCR are kept separately; the bundle retains source metadata and
fingerprint references. Readings and reasons may quote source text, so exported histories must
receive the same privacy review as their contents. Hashes prove byte correspondence, not identity, rights, correctness or freshness.

**Export contribution receipt** remains the *readable view*: it is the latest receipt alone, for
people who want to read one record without a decoder. It cannot reopen on a device that already
retains creator history for the same record; the bundle can.

## Reading a bundle outside the browser

`scripts/verify-contribution.mjs` now accepts both files. For a bundle it verifies the chain and the
latest receipt, prints a summary, and can write the exact latest receipt bytes:

```
node scripts/verify-contribution.mjs contribution.history.json \
  [--expected-genesis HEX] [--expected-tip HEX] [--expected-sha256 HEX] \
  [--extract-latest-receipt latest.json]
```

`--expected-tip` turns "self-consistent" into "matches the checkpoint I was given": a stale or
rolled-back bundle is refused with `Expected tip mismatch`. Extraction refuses to overwrite.
Budgets apply before parsing (bundle text ≤ 92 MiB, snapshots ≤ 64 MiB aggregate, receipt ≤ 2 MiB).

## Canonical synthetic example

`examples/synthetic-contribution/` holds an owned synthetic bundle with two checkpoints, two
contributors, one AI-assistance note, one mentor `needs_review`, one reviewer `disputed`, two hOCR-pinned
readings and one declared (not executed) model record. `HASHES.json` records bytes, SHA-256, genesis
and tip. It is regenerated by `node scripts/make-synthetic-contribution.mjs` (ids and times are fixed
in the script; regenerate only when the format changes, then update HASHES.json and the test).
No real source, no real person, no factual correction is asserted.

## Offline validation in under five minutes

1. `node scripts/verify-contribution.mjs examples/synthetic-contribution/contribution.history.json --expected-genesis $(jq -r .genesis examples/synthetic-contribution/HASHES.json) --expected-tip $(jq -r .tip examples/synthetic-contribution/HASHES.json)` → `verification: SELF_CONSISTENT_HISTORY_WITH_INDEPENDENT_GENESIS_AND_TIP`, `checkpoints: 2`.
2. Add `--extract-latest-receipt /tmp/latest.json`; `shasum -a 256 /tmp/latest.json` equals `files["latest-receipt.json"].sha256` in HASHES.json.
3. `node scripts/verify-contribution.mjs /tmp/latest.json` → `format: garrison.cairn.receipt.v0.1`, `readings: 2`, `mentorReviews: 1`, `disputed: 1`.
4. Change one character inside the extracted receipt and rerun step 3 → `REFUSED … integrity`.
5. `node --test tests/contribution-file.test.mjs` → 4 pass (round trip, reader, refusals, example hashes).

No network, model or browser is involved. A browser reopen of the same bundle is covered by the
existing `tests/creator-history-wiring.test.mjs` and the Playwright walkthroughs.

## Functional versus proposed limits

Functional now: single default file, exact snapshots, stale/rollback/tamper refusal, Node reader,
readable extraction, example and tests. Proposed, not implemented: per-revision prior-content hash;
a bundle-aware "readable view" button in the UI (today the readable receipt is a separate export);
native Garrison WAL fields; signatures, anchoring, submission or host adoption. The experimental
public WAL remains a separate workbench and is referenced, not merged.
